# 对话上下文管理与历史压缩机制 (Context Management & Compaction)

> 本文档记录 FlashAgent 的上下文预算机制、多轮对话压缩架构，以及大模型时代的后续演进规划。

## 1. 核心设计理念：双层解耦架构

FlashAgent 采用界面渲染与线路传输物理隔离的 Codex-style 双层设计：

- **界面层（UI DOM）**：
  **100% 完整保留所有历史记录**。无论会话持续了多少轮、被压缩了多少次，用户在窗口中看到的聊天气泡、展开的工具调用结果折叠卡片、代码块、思考过程没有任何一条会被物理删除。
- **线路层（Send Payload）**：
  采用**“前情提要（复工文档）+ 最近任务轮次滑动窗口（Sliding Window）”**的结构组装给模型的输入：
  ```text
  [消息 0 (合成 User 角色)]: # 复工文档 (Recap Doc - 结构化提取的事实、文件变更、失败台账、当前状态)
  [消息 1 .. K (原生多轮)]: 完整保留的最近若干轮对话（保留原始 user/assistant 文本与工具调用轨迹）
  [最后一条 User]: 用户刚输入的当前指令
  ```

## 2. 注意力预算与自动压缩

- **默认预算**：`200,000` tokens（支持在设置中自定义 4k ~ 2,000k）。
- **保留区（85% 预算）**：约 170,000 tokens。按完整用户任务轮次从最新向最旧倒推保留。只要倒推累计未超过 85%，全部原汁原味重放。
- **自动触发线（95% 预算）**：约 190,000 tokens。当预估或服务端返回的 Token 数量达到 95% 时，在下次发送新消息前自动启动压缩。
- **死锁破局机制（Deadlock Breaker）**：
  当单轮任务自身极其庞大导致 `keepStart <= covered` 时，系统自动解除“最新轮无条件保留”限制，将超长历史提炼浓缩为 5 节复工文档，彻底杜绝单轮长任务死锁导致上下文溢出的问题。
- **手动就地压缩（In-place Compaction）**：
  输入框左侧的上下文圆环（`chat-context-ring`）支持鼠标点击。用户看到圆环变红（达到高水位）时，可随时点击就地压缩，圆环即时回缩变绿。
- **压缩模型智能降级**：
  主进程在调用指定的压缩模型遇到 404 / 不存在时，零延迟无缝降级到当前对话使用的聊天模型，并配合 `autoRepairRecapDoc` 进行 Markdown 标题与缺项自愈，100% 确保复工文档合规生成。

## 3. 后续规划优化点（待落地规划）

以下 4 个优化方向记录于此，供后续版本迭代实施：

### 优化点 1：大窗口下工具单次输出上限释放（提升吞吐，减少 Agent 盲读）
- **现状**：单次工具调用输出硬截断为 `12,000` 字符（约 3000 tokens）。
- **优化方案**：在 200k~1M 充裕预算下，将单次输出上限适度放大至 `30,000~40,000` 字符（约 8k~10k tokens，仅占 200k 窗口的 4%~5%），避免阅读 500~800 行源码时被拦腰截断，大幅减少 Agent 重复翻页调用的往返延迟。

### 优化点 2：高水位到达时的主动微提醒（消除视觉盲区）
- **现状**：AI 生成完毕后上下文变红时，仅依赖左下角圆环变色，部分用户容易忽略。
- **优化方案**：当 AI 回复完毕、上下文首次进入高水位（>= 85% 变红）时，输入框上方温和浮现一条轻量气泡提示（4 秒自动淡出）：
  *“💡 上下文已接近上限，可点击左下角圆环立即压缩，或继续发送消息自动压缩”*。

### 优化点 3：设置页提供常用模型窗口预设胶囊（Context Presets）
- **现状**：用户在不同供应商（如 DeepSeek 64k/128k、Claude 200k、Kimi 200k、Gemini 1M）切换时，需要手动计算并输入 6 位数字。
- **优化方案**：在设置页“上下文窗口”输入框下方提供快速点击胶囊：`[ 128k ]` `[ 200k (推荐) ]` `[ 500k ]` `[ 1M ]`，一键切换。

### 优化点 4：系统真实文件修改台账强注入复工文档（防止多轮记忆漂移）
- **现状**：多轮连续压缩后，复工文档完全依靠大模型的二次总结，早期的某些修改细节可能会被简写遗漏。
- **优化方案**：主进程底层已精准维护 `[Active Edits in this Task]`（真实写入/修改过的文件路径）。在生成复工文档时，强制把真实底层文件台账作为“不可动摇的地面真值”注入第 3 节（`涉及文件与当前状态`），杜绝模型在跨多天或长对话中的记忆漂移。
