# Security Policy

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub issues.

Instead, contact the maintainer privately before disclosure. If you publish this repository publicly, replace this document with your preferred private reporting channel, for example:

- a dedicated security email address
- a private contact form
- GitHub Security Advisories

## What to Report

Examples of in-scope security issues:

- API key exposure
- unsafe handling of local configuration or secrets
- privilege or permission misuse
- remote code execution or command injection risks
- unsafe external content handling

## Response Expectations

The maintainer should:

- acknowledge the report within a reasonable time
- validate and triage the issue
- coordinate disclosure after a fix or mitigation is available
