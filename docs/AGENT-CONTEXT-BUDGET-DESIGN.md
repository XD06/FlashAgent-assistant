# Agent 工作上下文预算设计

> **状态**：第一阶段计量已实现并完成一次真实 Agent 回归；动态预算准入仍是提案。
> **更新时间**：2026-08-01
> **适用范围**：独立 AI 对话窗口的 Agent 模式、跨消息历史回放、工具结果回放与历史压缩。

## 1. 决策摘要

FlashAgent-assistant 的 Agent 不是以长程自治为核心目标，而是以**当前任务的准确性、可验证性和 token 效率**为核心。模型应围绕用户此刻交办的工作保持完整证据，避免因为固定的调用次数或轮数过早遗忘；更早历史才按价值逐层降级。

因此，本设计固定的是**工作上下文预算**，而不是“保留最近 N 轮”的数字。可以完整保留多少任务轮，应由实际 payload 的 token 占用决定。

## 2. 术语

为避免代码和产品讨论中的“轮”混用，本文统一采用以下术语：

| 术语 | 定义 |
| --- | --- |
| 用户任务轮 | 从用户发送一条消息开始，到用户发送下一条消息前结束的完整工作过程。期间可包含多个模型请求和工具调用。本文中的“轮”均指此概念。 |
| 模型请求 | 向模型服务商发起的一次 API 请求。 |
| 工具迭代 | 一个模型请求返回工具调用，应用执行工具并将结果提供给下一次模型请求的过程。一个工具迭代可包含多个工具调用。 |
| 完整工具结果 | 在模型上下文中保留的工具结果正文；仍受单次结果安全上限保护，不等同于无限制的原始字节流。 |
| 工具结果降级 | 保留工具名称、参数摘要、执行状态和固定提示，省略较早工具结果正文。它不是对话压缩。 |
| 历史压缩 | 将更早的多个用户任务轮替换为一条结构化“复工文档”消息。原始历史仍保留在本地 UI。 |

现有 `ChatTurn` 是单条消息记录，用户消息和助手消息各自占一条，不能直接视为一个用户任务轮。后续实现必须显式建立用户任务轮边界。

## 3. 不变量

1. 当前用户任务轮只要仍能装入工作上下文预算，就保留完整工具结果，不因固定工具迭代次数主动压缩或降级。
2. 较早用户任务轮按“完整结果 -> 固定格式工具结果 -> 复工文档”逐层降级；优先处理最早历史，避免损害最近工作证据。
3. 所有原始工具输出和完整本地对话均保存在本地，不因模型上下文降级而丢失。
4. 任何 payload 截断必须可解释、可观测且先经过历史层级降级；不得静默省略关键任务状态。
5. 用户交互由语义边界触发，例如需求歧义、重要方案选择、风险操作或验证失败；不得仅因固定调用次数打断用户。
6. `maxToolRounds` 等固定数值只作为失控保护，不作为正常上下文保留策略。

## 4. 现状与问题

当前实现已经具备三个有价值的基础：

- 跨轮工具调用以原生 `tool_calls/tool_result` 协议回放，避免把执行记录伪装成模型文本。
- 更早历史可压缩为固定五节的复工文档，并在本地合并时限制摘要大小。
- 工具结果设有单次上限，并在较早模型工具迭代中改写为固定提示，防止无限增长。

但上下文控制存在两个不同层次：

1. 渲染层会在下一条用户消息发送前，根据 `contextWindowTokens` 对较早历史进行压缩。
2. 主进程的同一用户任务轮内工具循环独立运行，当前没有使用该预算做下一次模型请求的准入判断；它主要依赖固定的工具迭代保留窗口和最终上限。

这会导致“工作上下文预算”只约束跨用户消息历史，不能约束同一任务轮内的连续模型请求。固定保留 25 个工具迭代也不等于固定保留 25 个工具调用，因为一个模型请求可以返回多个工具调用。

## 5. 预算模型

### 5.1 输入预算

设：

- `B`：用户配置的工作上下文预算（`contextWindowTokens`）。它是注意力预算，不是模型物理最大上下文长度。
- `R`：为下一次模型回复、工具调用参数和推理预留的输出预算。
- `M`：估算误差安全余量。
- `I = B - R - M`：下一次请求允许的最大输入 token 数。

在发送任何模型请求前，必须判断：

```text
projectedPromptTokens <= I
```

`R` 必须显式配置或由请求模式确定；若服务商 API 支持，应将对应的最大输出参数同时写入请求。没有输出上限，输入预算无法形成可靠边界。

### 5.2 占用组成

每次预测必须覆盖实际会进入请求的全部部分：

- 系统提示、Agent 规则和动态工作目录信息；
- 工具定义，包括 Web Search、用户选择注入的 MCP 与本地 Agent 工具 schema；
- 全局记忆、项目记忆和 Skills 元数据；
- 复工文档、历史用户/助手消息、工具调用参数和工具结果；
- 当前用户输入、内联文件、图片和中途追加指令；
- 上一次模型回复中将被回放的 tool call / reasoning 所需结构。

### 5.3 真实 usage 优先，估算兜底

支持 usage 的服务商应使用最新一次真实 `prompt_tokens` 作为基线。下一次请求只估算相对该请求新增的工具调用、工具结果和用户输入，避免反复扫描或重复计算静态部分。

不返回 usage 的服务商使用脚本感知估算：CJK 文本、非 CJK 文本、工具参数、文件正文和图片分别计量。估算系数应按 `provider + model` 保存近期实测校准值：当后续获得真实 usage 时，以“真实值 / 估算值”更新系数，并将安全余量覆盖历史低估的高分位误差。图片在没有服务商精确计费信息时采用保守上界，并优先记录尺寸和 provider 的图像 detail 策略。

此模型不会承诺跨所有第三方服务商的绝对 token 精度；它保证在有 usage 时以真实值为锚，在无 usage 时保守退化且可通过数据校准。

## 6. 动态保留策略

### 6.1 新用户任务轮开始前

构建请求时，从最新已完成的用户任务轮向前尝试装入 `I`：

1. 最近任务轮优先保留完整工具结果。
2. 当完整结果无法装入时，先把更早任务轮的工具结果降为固定格式，保留调用身份、参数摘要、状态、文件路径、命令摘要、退出码和验证结论。
3. 若仍无法装入，仅压缩最早且必要的一段历史为复工文档；复工文档继续保留原始目标、当前文件状态、失败路径和下一步。
4. 直到 payload 满足预算，才发送当前用户输入。

“最近几轮”由这个回退过程自然确定，不使用固定比例、固定消息条数或固定用户任务轮数。

### 6.2 当前用户任务轮内

每次工具执行完成后，在发起下一次模型请求前进行预算准入：

```text
projectedNextPrompt = lastMeasuredPrompt + newlyAppendedModelAndToolMaterial
```

若准入通过，继续执行并保留当前任务轮的完整工具结果。不得为了节省 token 而提前压缩当前任务轮。

若准入失败，应用不得静默截断当前证据，也不得自动把当前任务轮伪装成已完成。它应明确进入“上下文边界”状态：展示已验证的操作、改动、验证结果、阻塞点和继续所需动作。用户下一次发送“继续”或新指令后，刚完成的任务轮才成为较早历史，可按 6.1 的规则降级或压缩。

这将用户交互限制在真正的容量边界，不以固定调用次数打断清晰、可逆的连续工作。

### 6.3 提示词的职责

提示词只负责提高工具调用质量，不承担强制预算控制。Agent 规则应要求模型：

```text
将任务拆成可验证的小步骤。每次工具调用都应解决当前一个明确问题；
优先精确搜索、限定范围读取和最小修改。
需求明确且可逆时持续推进；只有存在重要方案选择、风险操作或验证失败时才请求用户决定。
不要为了展示进度而调用工具，也不要因固定调用次数提前停止。
```

### 6.4 记忆、Skills 与 MCP 的注入策略

上下文预算不应替用户否决工具能力。MCP 是否进入请求由用户在扩展面板中显式控制，并且独立于“普通模式 / Agent 模式”：

- 用户启用并选择“注入”的 MCP 服务，其工具 schema 可同时用于普通快速问答和 Agent 任务；普通模式不因模式名称而被强制剥夺 MCP 能力。
- 用户关闭服务或取消“注入”后，该服务的 schema 不进入请求，也不能被模型调用。
- Agent 开关只决定是否注入本地文件、目录和命令工具，以及是否附带工作目录规则；它不替代用户对 MCP 的选择。
- 扩展面板应展示每个已选择注入服务的工具数量与预计 token 占用，让用户在能力和注意力成本之间自行取舍。

当前实现已将“连接”和“注入”拆为独立开关：连接仅维护 MCP 会话；只有已连接且用户打开
“注入”的服务会贡献 schema，并且主进程会拒绝执行未注入 MCP 工具名。旧配置迁移后保持原有
“已连接即已注入”行为；新建服务默认不连接也不注入。工具数量已在连接状态中可见，schema token
估算会进入每次请求的上下文计量；每服务的预估展示留待后续 UI 迭代。

记忆采用不同的优先级，而不是全部关闭：当前工作目录的项目规则和用户明确标记的少量核心偏好属于硬约束，可始终注入但必须有严格大小上限；其他全局偏好和历史事实属于软记忆，应按用户选择或按需检索。Skills 在 Agent 模式下仅注入简短元数据目录，具体指令仍由模型在任务匹配时读取。

## 7. 工程验证方案

### 7.1 先观测，后强制

第一阶段只记录指标，不改变行为。所有指标不得记录用户文本、文件正文、密钥或命令输出，只记录长度、数量、类别和结果状态。

建议采集：

- 每次模型请求的真实 `prompt_tokens`、预测值、预测误差和可用预算；
- 系统提示、工具 schema、记忆、历史、当前输入、图片和工具结果各自的 token 份额；
- 每个用户任务轮中的模型请求数、工具调用数、工具输出字符数和当前任务轮是否完整保留；
- 工具结果降级次数、历史压缩范围、上下文边界次数和“继续”后的重读次数；
- provider / model 是否提供 usage。

第二阶段在同一批脱敏任务记录上以影子模式比较“现有固定窗口”与“动态预算”决策，只输出两者是否会压缩、降级或触发边界，不改变真实请求。

第三阶段仅对通过验证的 provider / model 组合启用预算准入，再逐步扩展到无 usage 的保守估算路径。

### 7.2 回归任务集

验证至少覆盖以下场景：

| 场景 | 关注点 |
| --- | --- |
| 单文件定位、修改、测试 | 当前任务轮完整工具结果可用，且无需无意义重读。 |
| 多文件小型重构 | 最近任务轮优先保留，较早历史按最小前缀压缩。 |
| 大文件读取与限定行重读 | 单次结果上限、关键头尾和精确重读的平衡。 |
| 高输出构建/测试命令 | 退出码、失败摘要和末尾错误信息在降级后仍可验证。 |
| 截图、内联文件与文本混合 | 图像和附件成本进入预测，避免低估。 |
| 支持与不支持 usage 的服务商 | 真实 usage 路径与保守估算路径均不会静默越界。 |
| 用户中途追加指令 | 追加内容在下一次安全模型请求中按顺序生效。 |

### 7.3 验收标准

- 有真实 usage 的请求：预测低估必须被 `M` 覆盖；一旦发现预算越界，记录原因并收紧对应模型校准系数。
- 当前用户任务轮在预算允许时不发生工具结果降级或对话压缩。
- 较早任务轮降级后，模型仍能识别工具名称、路径/命令摘要、状态、验证结果和需重读的对象。
- 达到容量边界时，用户看到明确、基于真实工具结果的状态，而不是静默截断或未经验证的“已完成”。
- 与现有策略相比，在相同回归任务上不增加无效重复读取，不降低测试/命令失败定位能力。
- 用户启用注入的 MCP 服务后，普通快速问答和 Agent 任务均可调用其工具；用户未选择注入的服务不得出现在请求工具列表中。

## 8. 实施顺序

1. 在数据模型中建立用户任务轮边界，替代把单条 `ChatTurn` 当作“轮”的隐式假设。
2. 为 MCP 服务补充用户可见的启用与注入状态，并使普通模式与 Agent 模式都严格遵循该选择。
3. 提取统一的 payload 计量器，输出分段 token 估算与真实 usage 校准数据。
4. 以影子模式运行动态保留策略，补齐回归任务和边界样本。
5. 先在跨用户任务历史上启用“最小必要前缀压缩”，保持当前用户任务轮的完整性。
6. 在 Agent 内循环加入预算准入和上下文边界状态。
7. 最后才依据真实指标评估 `maxToolRounds`、单次工具结果上限和输出预留预算；不预设将 50 改为 25。

## 9. 不采用的方案

| 方案 | 不采用原因 |
| --- | --- |
| 固定保留最近 3 / 5 / 25 轮 | 轮数与 token 占用没有稳定关系，会在短任务浪费上下文、在高输出任务过早溢出。 |
| 达到固定工具调用数就要求用户继续 | 打断清晰且可逆的任务，增加用户交互，不提高准确性。 |
| 当前用户任务轮内主动压缩全部工具输出 | 会破坏连续决策证据，诱发重复读取和额外 token 消耗。 |
| 仅靠提示词让模型少调用工具 | 提示词无法对第三方模型形成硬性容量边界，只能作为效率引导。 |
| 静默截断或只保留最近消息 | 容易丢失文件状态和已验证结论，且用户难以察觉。 |

### 多场景校准（2026-08-01）

为避免同一英文小任务反复采样带来错误自信，E2E 驱动新增了三个可选场景：中文系统提示与用户
任务、约 24 KB 的受控 `read_file` 结果，以及实际发送一张无内容的 1×1 PNG。驱动在每次运行前
删除该场景上次生成的标记文件，并记录每个工具结果的总字符数和最大字符数；因此旧文件不能造成
假通过，且大输出场景会额外断言模型确实调用了 `read_file`。日志和结果文件仍只包含数值、状态和
场景名。

| 场景 | 请求 / 工具 / 错误 | 关键输入 | 估算与真实 `prompt_tokens` | 结论 |
| --- | --- | --- | --- | --- |
| `cjk` | 5 / 5 / 0 | 工具结果共 2,079 字符 | 1,050–2,049 / 1,240–2,755 | 全部低估，约 15.3%–25.6%。中文任务不能仅凭字符数估算就视为安全。 |
| `large-output` | 4 / 7 / 0 | 工具结果共 27,897 字符，单次最大 25,138 字符 | 1,092–4,919 / 1,268–4,867 | 首次低估约 13.9%；读入大文件后估算高出约 1.1%–13.4%。工具文本段与静态段不应共用一个放大倍率。 |
| `image` | 4 / 5 / 0 | 一张 1×1 PNG，工具结果共 2,176 字符 | 3,091–4,178 / 1,253–2,828 | 固定 2,000 token 图像预估高出约 47.7%–146.7%。该无内容小图不能代表真实截图，但证明固定图像常量过粗。 |

三种场景均返回 usage，所有标记创建和语法检查均成功，工具错误为零。基于这组结果：

1. **禁止使用一个全局校准系数。** 系统提示、工具 schema、普通文本、工具结果和图像必须保留
   独立指标；若以后启用硬预算，校准值至少要按 `provider + model + 输入段` 保存。
2. **图像必须采集数值元数据。** 后续计量应记录图片的像素尺寸、编码字节数和 provider 的 detail
   策略（不记录图像内容），并用真实截图尺寸补样。1×1 图片只能证明现有上界很保守，不能推导
   截图、照片或多图请求的成本。
3. **继续保持影子模式。** 当前样本同时出现 25% 级低估和 100% 级高估；直接放大总估算会在部分
   场景过早打断任务，直接缩小又会越过真实输入边界。只有完成分段校准并得出有证据的 `M` 后，
   才能对某个 provider/model 组合启用准入。

复现命令为 `pnpm e2e:agent-context -- cjk`、`pnpm e2e:agent-context -- large-output` 和
`pnpm e2e:agent-context -- image`；默认命令保留英文基准场景。

## 12. 跨用户任务轮保留实现记录

**日期**：2026-08-01

跨用户任务轮的第一个运行时阶段现已实现，范围只覆盖用户发送下一条消息前的历史构建；同一用户
任务轮内的预算准入仍保持影子模式。具体行为如下：

1. 发送前根据 `taskRoundId` 将记录分组为完整用户任务轮；旧会话没有该字段时，兼容地以每个用户
   消息作为一轮起点。压缩切点只能落在轮边界，不能把某次用户请求与其工具证据、助手结论拆开。
2. 从最新的完整任务轮向前装入 `KEEP_RECENT_TOKEN_RATIO` 所定义的 token 预算。不存在最少/最多
   保留 N 条消息或 N 个任务轮的普通策略；传输消息上限只作为安全边界，并为摘要与新用户消息预留
   空位。最新完整任务轮即使单独超预算也保留。
3. 跨轮工具输出采用同一选择结果：预算窗口内的完整任务轮保留已执行工具的输出，较早轮只回放
   工具身份、参数摘要和状态。无 usage 的回退改为陈旧区字符压力与硬传输上限，不再要求“至少 6
   条消息”才压缩。
4. 既有摘要不会被重写。若很早版本的 `covered` 恰好位于旧的单条消息边界，下一次压缩会从该位置
   继续纳入内容；新产生的 `covered` 始终是完整任务轮边界，因此不会丢失已保存的历史。

真实 `pnpm e2e:compaction` 回归使用旧应用目录中的本机 provider 配置进行只读回退，未复制或修改
设置。8 个模拟用户任务轮中，预算选择在索引 6 切分，前 6 条消息压缩为 687 字符的复工文档；摘要
五节均通过结构校验，并保留 `3500`、`.rotate.lock`、`gzip`、`fs.watch`、`config.js` 五项早期事实。
后续提问只携带该摘要和近因区，模型仍正确回答超时值、锁文件与修改文件；该请求真实
`prompt_tokens` 为 676。

这证明跨用户任务轮的原子保留与复工文档连续性已经可运行。它不证明内循环硬预算已安全：该部分仍
需要第 11 节的分段校准结果来确定 `M` 和输入准入边界。
